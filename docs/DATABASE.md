# Oracle Database Design

## DBMS

Oracle Database 사용.

모든 SQL / DDL / DML은 Oracle 기준으로 작성한다.

---

## Database Role

Oracle은 서비스의 관계형 데이터를 관리한다.

주요 데이터:
- 사용자
- 계정
- AI 대화
- 메시지
- 사용자 지식
- 문서 메타데이터
- AI/RAG 관련 메타데이터

Vector 데이터의 실제 저장 방식은 RAG 설계에 따라 결정한다.

---

## Oracle Rules

Oracle 데이터 타입을 사용한다.

주요 타입:
- VARCHAR2
- NUMBER
- CLOB
- DATE
- TIMESTAMP

다른 DBMS 전용 문법을 사용하지 않는다.

사용 금지 예:
- AUTO_INCREMENT
- LONGTEXT
- MySQL 전용 문법
- MariaDB 전용 문법
- PostgreSQL 전용 문법

Oracle 버전에 따라 지원 여부가 달라지는 기능은 실제 버전을 확인한다.

---

## Schema Rules

확정된 Schema만 구현한다.

Codex가 임의로 다음 항목을 생성하거나 변경하지 않는다.

- TABLE
- COLUMN
- PK
- FK
- UNIQUE
- INDEX
- SEQUENCE
- TRIGGER

변경이 필요한 경우 기존 설계와 실제 코드를 먼저 확인한다.

---

## Relationship Policy

논리적인 테이블 관계와 실제 FK Constraint는 구분한다.

FK를 무조건 사용하거나 무조건 제거하지 않는다.

다음 사항을 고려하여 결정한다.

- 데이터 무결성
- 삭제 정책
- 성능
- 조회 패턴
- 저장 패턴
- 운영 방식

코드에서 FK 존재 여부를 추측하지 않는다.

## Confirmed Schema

아래 Schema는 현재 Oracle DB에 실제 생성된 테이블 구조이다.
DB 관련 구현 시 아래 테이블명과 컬럼명을 기준으로 한다.
존재하지 않는 테이블이나 컬럼을 임의로 생성하거나 추측하지 않는다.

### USERS

```sql
CREATE TABLE USERS (
    USER_ID NUMBER GENERATED BY DEFAULT AS IDENTITY,
    EMAIL VARCHAR2(255) NOT NULL,
    PASSWORD VARCHAR2(255) NOT NULL,
    NAME VARCHAR2(100) NOT NULL,
    STATUS VARCHAR2(20) DEFAULT 'ACTIVE' NOT NULL,
    CREATED_AT TIMESTAMP DEFAULT CURRENT_TIMESTAMP NOT NULL,
    UPDATED_AT TIMESTAMP,

    CONSTRAINT PK_USERS PRIMARY KEY (USER_ID),
    CONSTRAINT UK_USERS_EMAIL UNIQUE (EMAIL)
);
```

### CONVERSATIONS

```sql
CREATE TABLE CONVERSATIONS (
    CONVERSATION_ID NUMBER GENERATED BY DEFAULT AS IDENTITY,
    USER_ID NUMBER NOT NULL,
    TITLE VARCHAR2(300) NOT NULL,
    STATUS VARCHAR2(20) DEFAULT 'ACTIVE' NOT NULL,
    CREATED_AT TIMESTAMP DEFAULT CURRENT_TIMESTAMP NOT NULL,
    UPDATED_AT TIMESTAMP,

    CONSTRAINT PK_CONVERSATIONS PRIMARY KEY (CONVERSATION_ID),

    CONSTRAINT FK_CONVERSATIONS_USER
        FOREIGN KEY (USER_ID)
        REFERENCES USERS(USER_ID)
);
```

### MESSAGES

```sql
CREATE TABLE MESSAGES (
    MESSAGE_ID NUMBER GENERATED BY DEFAULT AS IDENTITY,
    CONVERSATION_ID NUMBER NOT NULL,
    ROLE VARCHAR2(20) NOT NULL,
    CONTENT CLOB NOT NULL,
    CREATED_AT TIMESTAMP DEFAULT CURRENT_TIMESTAMP NOT NULL,

    CONSTRAINT PK_MESSAGES PRIMARY KEY (MESSAGE_ID),

    CONSTRAINT FK_MESSAGES_CONVERSATION
        FOREIGN KEY (CONVERSATION_ID)
        REFERENCES CONVERSATIONS(CONVERSATION_ID)
);
```

### KNOWLEDGES

```sql
CREATE TABLE KNOWLEDGES (
    KNOWLEDGE_ID NUMBER GENERATED BY DEFAULT AS IDENTITY,
    USER_ID NUMBER NOT NULL,
    NAME VARCHAR2(200) NOT NULL,
    DESCRIPTION VARCHAR2(1000),
    STATUS VARCHAR2(20) DEFAULT 'ACTIVE' NOT NULL,
    CREATED_AT TIMESTAMP DEFAULT CURRENT_TIMESTAMP NOT NULL,
    UPDATED_AT TIMESTAMP,

    CONSTRAINT PK_KNOWLEDGES PRIMARY KEY (KNOWLEDGE_ID),

    CONSTRAINT FK_KNOWLEDGES_USER
        FOREIGN KEY (USER_ID)
        REFERENCES USERS(USER_ID)
);
```

### CONVERSATION_KNOWLEDGE

CONVERSATIONS와 KNOWLEDGES의 N:M 관계를 연결하는 중간 테이블.

```sql
CREATE TABLE CONVERSATION_KNOWLEDGE (
    CONVERSATION_ID NUMBER NOT NULL,
    KNOWLEDGE_ID NUMBER NOT NULL,
    CREATED_AT TIMESTAMP DEFAULT CURRENT_TIMESTAMP NOT NULL,

    CONSTRAINT PK_CONVERSATION_KNOWLEDGE
        PRIMARY KEY (CONVERSATION_ID, KNOWLEDGE_ID),

    CONSTRAINT FK_CK_CONVERSATION
        FOREIGN KEY (CONVERSATION_ID)
        REFERENCES CONVERSATIONS(CONVERSATION_ID),

    CONSTRAINT FK_CK_KNOWLEDGE
        FOREIGN KEY (KNOWLEDGE_ID)
        REFERENCES KNOWLEDGES(KNOWLEDGE_ID)
);
```

### DOCUMENTS

원본 업로드 문서의 정보를 관리한다.

```sql
CREATE TABLE DOCUMENTS (
    DOCUMENT_ID NUMBER GENERATED BY DEFAULT AS IDENTITY,
    KNOWLEDGE_ID NUMBER NOT NULL,
    FILE_NAME VARCHAR2(500) NOT NULL,
    FILE_TYPE VARCHAR2(50),
    FILE_PATH VARCHAR2(1000),
    STATUS VARCHAR2(20) DEFAULT 'ACTIVE' NOT NULL,
    CREATED_AT TIMESTAMP DEFAULT CURRENT_TIMESTAMP NOT NULL,

    CONSTRAINT PK_DOCUMENTS PRIMARY KEY (DOCUMENT_ID),

    CONSTRAINT FK_DOCUMENTS_KNOWLEDGE
        FOREIGN KEY (KNOWLEDGE_ID)
        REFERENCES KNOWLEDGES(KNOWLEDGE_ID)
);
```

### DOCUMENT_CHUNKS

문서를 RAG 검색에 사용할 수 있도록 분할한 Chunk를 관리한다.

```sql
CREATE TABLE DOCUMENT_CHUNKS (
    CHUNK_ID NUMBER GENERATED BY DEFAULT AS IDENTITY,
    DOCUMENT_ID NUMBER NOT NULL,
    CHUNK_INDEX NUMBER NOT NULL,
    CONTENT CLOB NOT NULL,
    VECTOR_ID VARCHAR2(255),
    CREATED_AT TIMESTAMP DEFAULT CURRENT_TIMESTAMP NOT NULL,

    CONSTRAINT PK_DOCUMENT_CHUNKS PRIMARY KEY (CHUNK_ID),

    CONSTRAINT FK_CHUNKS_DOCUMENT
        FOREIGN KEY (DOCUMENT_ID)
        REFERENCES DOCUMENTS(DOCUMENT_ID),

    CONSTRAINT UK_DOCUMENT_CHUNK_INDEX
        UNIQUE (DOCUMENT_ID, CHUNK_INDEX)
);
```

```text
                │

CONVERSATIONS
       │
       └── N:M → KNOWLEDGES
              │
              └── CONVERSATION_KNOWLEDGE
```

## Database Rules

- DBMS: Oracle 21c
- PK 자동 생성: `GENERATED BY DEFAULT AS IDENTITY`
- 별도 Sequence는 사용하지 않는다.
- 실제 DB Schema에 없는 컬럼을 임의로 생성하지 않는다.
- 기존 PK/FK/UNIQUE 제약조건을 임의로 변경하지 않는다.
